# hxwl-11 儿童近视进展随访台

由「眼科验光记录」扩展而来：按患者、日期、眼别随访球镜、等效球镜（SE）与眼轴长度，
自动判定近视进展风险并留痕修订。React + Vite + TypeScript + CSS，数据存 localStorage，刷新后不丢失。

## 分层结构（数据 / 规则 / 页面分开）

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 领域类型 | `src/domain/types.ts` | 患者、复查、版本链、冲突等纯类型 |
| 数据层 | `src/data/` | localStorage 仓储与示例数据；唯一键约束、版本只追加 |
| 规则层 | `src/rules/` | 等效球镜、半年化进展、风险等级、时间线派生（纯函数） |
| 状态桥接 | `src/state/useFollowUp.ts` | 加载/写入数据，调用规则层派生视图 |
| 页面层 | `src/components/`、`src/App.tsx` | 录入、冲突、时间线、版本链等界面 |

## 业务规则

1. **唯一键 = 患者 + 日期 + 眼别**，同日同眼只留一条；重复保存返回冲突，
   冲突面板显示患者、日期、眼别与原值（球镜 / 柱镜 / SE / 眼轴 / 处置资料）。
2. **风险阈值**：相对同眼上一条复查，
   - 半年眼轴增长 **> 0.20 mm**，或
   - 半年等效球镜下降 **> 0.50 D**（即 SE 变化 < −0.50D）
   
   即转为**重点随访**。不足半年的间隔按 182.625 天换算为半年当量再判定（严格大于阈值）。
3. 触发重点随访时，**户外时长与处置计划必填**；缺任一项该条记录以**草稿**保存，
   时间线与统计中标为「草稿待补全」。未触发则正常归档。
4. **修改只能修订**：患者 / 日期 / 眼别不可改；测量值更新时自动新建带原因的版本，
   旧值完整保留在版本链（v1 初次录入 → vN 当前值）。
5. **一致性**：状态（常规 / 重点 / 草稿）不入库保存，每次渲染由规则层根据完整版本链
   和时间线实时重算，刷新后时间线、风险等级、版本链保持一致。
6. 等效球镜自动计算：`SE = 球镜 + 0.5 × 柱镜`。

## 本地运行

```bash
npm install
npm run dev      # http://localhost:5111
npm run build    # 类型检查 + 构建
npm test         # 规则层单元测试（vitest）
```

## 示例数据

- 李小宇（9 岁）：半年双眼眼轴 +0.30mm、SE −0.75D 越限，已填处置 → 重点随访
- 王芷晴（11 岁）：进展平稳 → 常规随访；最近一条含一次「誊录勘误」修订版本链
- 张乐乐（7 岁）：3 个月眼轴 +0.30mm 但处置资料缺失 → 草稿待补全
- 陈一一（6 岁）：仅基线复查
